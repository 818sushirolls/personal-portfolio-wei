## What it is

A classifier trained on the UCI Wine Quality dataset (red and white combined,
about 6,497 samples after dedup) that predicts whether a wine is **high
quality**, defined as `quality >= 7`. The positive class only shows up in
roughly 19% of the data, so this is fundamentally an imbalanced binary
classification problem.

The point of the project wasn't to win on accuracy. It was to build a small,
honest end-to-end ML workflow that I could trust: load, clean, split, fit,
evaluate, and compare configurations reproducibly.

## How it works

The pipeline is built as reusable data-processing and model-training modules
wrapped around `scikit-learn`. The key pieces:

1. **Stratified 60 / 20 / 20** train / validation / test split with a fixed
   random seed so the numbers are reproducible.
2. **Train-only preprocessing.** Every scaler, polynomial expansion, PCA
   decomposition, and KMeans cluster fit happens on the train fold and is
   only applied to validation and test. No information leaks across folds.
3. **Four feature spaces** compared head to head: identity, polynomial
   (degree 2), PCA (95% variance retained), and KMeans cluster distances.
4. **Five model families**: logistic regression, SVM (linear and RBF), KNN,
   decision tree, and an MLP stub.
5. **Grid search per model**, with the best configuration chosen on
   validation F1 before the test set is ever touched.

The combination of model x feature space x hyperparameters lands at 72
configurations, all trained and evaluated under the same protocol. The test
set is held out completely until the very last notebook, when one final
evaluation produces the headline numbers.

## What I learned

The big lesson was about **what the evaluation metric is actually telling
you.** The positive class is rare, so accuracy alone would be misleading.
A model that always predicted "not high quality" would score around 81%.
F1 on the positive class exposes the real failure modes.

Best test F1 landed around **0.49 with KNN + PCA (k = 1)**. Not glamorous,
but the dataset is noisy, the labels are coarse, and the `>= 7` cutoff is
genuinely hard to separate from `6`. The boundary is mushy in the data
itself. Polynomial features helped the linear models (LR, SVM) more than
they helped KNN, and KMeans cluster distances were uniformly the weakest
representation across every model family.

It was also the first time I treated train / eval discipline as **code**
rather than as intent. The pipeline can't cheat because the scaler and PCA
literally don't exist until training. Validation never sees test data, even
by accident.

## What I'd do next

A few directions:

- **Finish the MLP.** It's currently a stub. Curious whether a modest neural
  net beats KNN once it has the same disciplined preprocessing.
- **Threshold tuning.** The 0.5 cutoff is a default, not a decision.
  Sweeping it would let me trade precision against recall depending on what
  false positives versus false negatives are worth.
- **Treat quality as ordinal.** It really is — the labels are 3 through 9 in
  the raw data, with structure. Ordinal regression or ordered classification
  might recover signal that binary collapses away.
